## 4. Loop / Graph 設計

### 流程圖（文字版）
```
         (先討論、後生成)
   ┌─────────────────────────────────┐
   │ N0  討論主題與 Wiki schema       │  ← 決定主題=AI Agents、頁面欄位
   └───────────────┬─────────────────┘
                   ▼
   ┌─────────────────────────────────┐
   │ N1  取得資料 (search + fetch)    │◄──────────┐  每篇來源各跑一次
   └───────────────┬─────────────────┘           │  (迴圈 ×5)
                   ▼                               │
   ┌─────────────────────────────────┐           │
   │ N2  抽取重點 + 寫 Wiki 頁        │           │
   └───────────────┬─────────────────┘           │
                   ▼                               │
   ┌─────────────────────────────────┐   不通過   │
   │ N3  檢查：出處/數字/一致性 gate  │───────────┘  回到 N1 補來源或重抽
   └───────────────┬─────────────────┘
                   ▼ 通過
   ┌─────────────────────────────────┐
   │ N4  跨頁整合 → 統一定義          │
   └───────────────┬─────────────────┘
                   ▼
   ┌─────────────────────────────────┐
   │ N5  以 Wiki 為來源生成簡報草稿   │◄──────┐
   └───────────────┬─────────────────┘       │ 不通過
                   ▼                           │
   ┌─────────────────────────────────┐        │
   │ N6  檢查：簡報↔Wiki 對應/教學結構 │───────┘ 回到 N5 重生成該頁
   └───────────────┬─────────────────┘
                   ▼ 通過
   ┌─────────────────────────────────┐
   │ N7  發布 HTML 簡報 (產生連結)     │
   └─────────────────────────────────┘
```

### 哪些步驟會重複執行？
- **N1→N2→N3**：對每一篇來源重複一次（共 5 次）。每篇都要抓資料、抽重點、過檢查。
- **N5↔N6**：簡報每一頁（或每一個主張）都要「生成 → 對照 Wiki 檢查」，不通過就只重生成該頁。

### 哪些地方需要檢查 / 重新生成？
- **N3（來源檢查 gate）**：檢查每個主張是否有出處、數字是否與原文一致、各頁說法是否矛盾。不通過 → 回 N1 補抓或重抽。
- **N6（簡報檢查 gate）**：檢查簡報每句是否都能對應到 Wiki、數字出處是否正確、教學結構是否由淺入深。不通過 → 回 N5 重生成。

### 為什麼這樣設計？
- **先討論後生成（N0）**：先把 schema 與主題範圍講清楚，避免後面每頁格式不一致、要大改。
- **把檢查做成獨立 gate（N3、N6）而非最後才檢查**：Agent 最常見的錯是「幻覺 / 編造數字」，越晚發現、錯誤傳播越廣。把檢查緊貼在「抽取」與「生成」之後，能在錯誤擴散前攔截。
- **以 Wiki 為單一事實來源**：簡報只能引用 Wiki 已驗證的內容，確保「Wiki ↔ 簡報」明確對應（評分加分項）。

## 6. 反思

**哪一個節點最常出錯？**
最常出錯的是 **N2「抽取重點」**，特別是**具體數字與分類**：模型傾向把記得的概念直接寫出來，容易出現「數字接近但不精確」或「把某方法歸錯類」（例如 ReAct 的歸類、34%/10% 的數字）。這對應 Wiki 來源本身提到的限制——自然語言輸出不可靠、會自信地出錯。

**發現問題後，把檢查往前移到了哪一個步驟？**
原本打算「最後做完簡報再一次檢查」（只有 N6）。實際執行後，把檢查**往前移到 N3**，也就是**每抽完一篇來源就立刻核對出處與數字**，不等到簡報階段。這樣錯誤在進入 Wiki 之前就被攔下，不會再傳到簡報。

**有沒有因此修改 workflow / graph？為什麼？**
有。新增了 **N3 這個「來源 / 數字 / 一致性」gate**，並定下一條規則：**簡報（N5）只能引用已通過 N3 的 Wiki 內容**。理由是 Wiki 是簡報的單一事實來源，把關口設在資料「進入 Wiki」的那一刻，可**降低錯誤往簡報傳播的機會**；但仍保留 **N6 核對生成內容**，形成前置（N3）＋後置（N6）的雙重把關，而非只靠一次檢查。
