先用一個生活比喻

把 LLM 想成一個很會讀書的大腦。

🧠 只有大腦

你問一句，它答一句。不能查最新資料、不能動手、答完就忘 —— 這是「一般的 LLM 呼叫」。

🧑‍🔧 大腦 + 手腳 + 筆記本

會列計畫、會查資料、會用工具、會把過程記下來、做錯會修正 —— 這就是 Agent。

👉 一句話：Agent 不是一顆更強的模型，而是一個「以 LLM 為大腦」的結構。

為什麼需要 Agent

「問一次」會遇到什麼問題？

  • 需要最新 / 外部資料時，模型只能用訓練時的舊知識 → 容易幻覺
  • 任務要很多步驟（先查 A、再算 B、再彙整）時，一次回答塞不下也容易出錯
  • 做錯了沒有修正機制，錯誤會一路沿著推理鏈傳播
  • 不能真的動手（查資料庫、執行程式、呼叫 API）

Agent 就是為了解決這些問題：讓 AI 會規劃、會行動、會檢查、會修正。

核心定義

Agent 與「一般 LLM 呼叫」差在哪？

一般 LLM 呼叫

輸入 → 輸出，一次結束。流程由人或固定程式決定。

AI Agent

LLM 動態主導自己的流程與工具使用，在一個會回饋結果的環境中，以迴圈朝目標前進。

Agents：LLM「maintaining control over how they accomplish tasks.」
— Anthropic, Building Effective Agents
核心架構

Agent＝LLM（大腦）＋ 三大元件

🗺️ Planning 規劃
把大任務拆成子目標、並反思修正
🧠 LLM
核心控制器 / 大腦
🔧 Tool use 工具
呼叫外部 API / 程式，取得模型沒有的能力
💾 Memory 記憶
短期＝context window；長期＝外部向量資料庫

此架構為最廣被引用的框架 — Lilian Weng, LLM Powered Autonomous Agents（2023）

元件一

🗺️ Planning：先想清楚怎麼做

任務拆解

Chain of Thought：一步一步想。
Tree of Thoughts：每步產生多個想法，像樹一樣搜尋最佳路徑。

自我反思

從過去行動學習、修正未來決策。代表方法：ReAct、Reflexion（後面詳講）。

重點：把一個「太大、一次做不完」的任務，拆成可一步步完成的子目標。

元件二

💾 Memory：短期與長期記憶

短期記憶

放在 context window 裡的資訊（這次對話看得到的內容）。容量有限。

長期記憶

存在外部向量資料庫，需要時用快速相似度搜尋（ANN/MIPS）撈回來，突破 context 限制。

類比：短期＝桌面上攤開的紙；長期＝旁邊一整櫃可隨時翻找的檔案。

元件三

🔧 Tool use：讓 AI 能「動手」

  • 呼叫外部 API / 程式，補足模型缺的能力：即時資料、精確計算、執行程式碼、查資料庫
  • MRKL：LLM 把問題路由給專家模組（可為計算機等符號工具）
  • Toolformer：訓練模型自己決定何時、怎麼呼叫工具
  • 工程重點：工具說明要像寫 prompt 一樣用心設計（ACI），並用「防呆」降低誤用

來源：Lilian Weng（2023）、Anthropic Building Effective Agents

核心迴圈（最重要）

ReAct：想一步、做一步、看結果

💭 Thought
推理：下一步該做什麼
→
⚙️ Action
行動：呼叫工具 / 查資料
→
👀 Observation
觀察：環境回傳的結果
↺

重複這個迴圈，直到得出答案或觸發停止條件（如最大次數）。

推理幫助建立與調整計畫；行動幫助取得外部資訊校正 → 兩者互補，減少幻覺。

實證：在 ALFWorld / WebShop 成功率比模仿與強化學習基線提高 34 / 10 個百分點（Yao et al., ICLR 2023）。

從失敗中學習

Reflexion：寫檢討、下次改進

🎬 Actor
嘗試（可用 ReAct）
→
⚖️ Evaluator
判斷成敗 / 打分
→
📝 Self-Reflection
用文字反省為何失敗
↺

反省存進記憶，下一回合當作額外脈絡 → 不用重新訓練模型就能進步。

和 ReAct 的差別：ReAct 是同一回合內想／做交錯；Reflexion 是跨回合累積反省。

代表數字：HumanEval 程式任務達 91% pass@1（Shinn et al., NeurIPS 2023）。

實務：別一上來就用 Agent

Workflow vs Agent：什麼時候用哪個？

　Workflow 工作流Agent 代理人
流程預先寫死的程式路徑LLM 動態自己決定
適合任務定義清楚、要可預測一致開放式、步數無法預測、需彈性
代價彈性低更貴、會累積錯誤，需大量測試

原則：先找最簡單的解，常常「單次 LLM＋檢索＋範例」就夠；只在必要時才升級成 Agent。

5 種常見 workflow 模式：Prompt chaining · Routing · Parallelization · Orchestrator-workers · Evaluator-optimizer（Anthropic）。

誠實面對

⚠️ 目前的限制與風險

📏 Context 有限

能放進的歷史 / 工具輸出有上限，檢索有幫助但不如完整 attention。

🧭 長程規劃難

長任務規劃、以及從意外錯誤中恢復，仍很困難。

🔌 介面不可靠

輸出格式錯誤、不照指令，很多程式碼都在解析與防呆。

加上：Agent 更貴、會累積錯誤，正式上線前要在 sandbox 大量測試並加 guardrails。

一句話帶走

總結

AI Agent＝以 LLM 為大腦的系統， 用 規劃＋記憶＋工具， 以「推理→行動→觀察」的迴圈自主朝目標前進，還能從失敗中修正。
  • 不懂技術也要記得的三件事：它會規劃、會動手、會修正
  • 不是越複雜越好 —— 先用最簡單的解
  • 它很強，但有限制，需要測試與把關
